# PRO 5000 高分辨率实验协议 v1

## 对照与数据流

P0 使用冻结官方权重。P1–P4 分别从同一权重严格加载原生网络。P1 是训练对照。各模型保留 48 通道 stride-2 细特征、原版双线性上采样、细窗相关和四步 RRU。在同一原生推理设置下比较最终匹配。native_skip_unused_matrix 开关控制原生推理的冗余相关矩阵，关闭时可保留该中间输出。

CCFI 对有效的 1/8 深层结构描述子作 4×4 掩码平均池化。两侧 1/32 token 投影至 96 维，可设 128。归一化 Q/K 的点积除以 0.15，两个方向共享同一相关矩阵的转置。源和目标 padding 在归一化前排除，空行的贡献为零。门控以非零 Sigmoid 小门值初始化。

BBR 在 1/32 的每行和每列分别选 8 个块，取并集。每个源块 16 个网格，每个目标块带半径 1 halo，最多 36 个网格。可选原范数过滤默认关闭。每对用升序 int32 键 i×N1+j 去重；按 chunk 计算 FP32 描述子点积，反向按 chunk 重新取特征。唯一键上一次性计算行、列 logsumexp，稀疏 MNN 在并列时取较小原网格 ID。阈值沿用原相对置信阈值。边预算默认超出即报错。显式 truncate 模式才会按各源行轮转保留，记录去重前后、截断和 GT 流失。

块监督合并双方向所有深度一致的中心投影。逐查询对多正块均匀取平均的双向交叉熵直接训练块级 logits。GT 注入率从 1 线性降至 0，在全程 30% optimizer updates 时结束。推理只使用预测路由。路由命中、halo 后覆盖、注入前 Top-M 命中分别计数。

LHG 在每个源格内对外观 logits 和块 logits 分别做 z-score，按 1 和 0.25 加权，固定默认 M=5。块分数辅助选择；基础 logits 与 P3 相同。两侧各自 64 维投影，候选分数、相对位置、局部熵及 margin 进入 MLP。默认四邻域源格，最多 12 条消息，每个节点按目标侧邻接距离加权聚合有界邻居的隐特征。残差层零初始化，更新仅写回选中边，所有原候选继续参与竞争。训练期可按相同退火率向每个源格替换至多一个 GT。排序负例要求源端 GT 可靠、目标端反向投影可见，双方向都至少偏离两格，选择同一行的最高分可靠负例。

## 几何与纹理

所有模型使用相同的居中采样坐标。OpenCV/K 的原图像素中心为整数，网络输入坐标的像素中心为 n+0.5。原坐标 p 到网络坐标为 (p+0.5)×(实际缩放后宽/原宽, 实际缩放后高/原高)。K 同步左乘该仿射，图像等比缩放取整，右/底补零。内部 scale0/1 为单位张量，传给原细匹配和 RRU 的坐标完全在输入平面。返回原图用逆变换。R1216 的长边有效 1200，R1024 的长边有效 1024。深度最近邻重采样至有效图域，零深度与 padding 无效。正深度、正投影深度、边界及 |z−d| ≤ 0.01+0.05d 共同界定可见性。高分辨率版本显式记录了原图整数中心与网络半整数中心的变换；相对于历史直接乘 scale 的适配，跨协议数值须分别报告。

开发点级分母使用 stride 8 源格中心 8i+4，目标落入合法半开粗格，正向可见。细点按自身坐标投影，源父格有任一可评价子点在原图 <2 px 即成功。粗严格命中、GT 入池、条件平均排名、固定分母 Recall@1/5/10、GT 在/不在 Top-M 及最终转换分别输出。并列排名按目标格 ID 升序。Margin 使用 GT 对最强其他候选的 log 双向概率差。精度和 EPE 使用有可见点级 GT 的子点，零分母留空。用于位姿的两侧细点均须在有效输入图域内。

纹理复用 src/texture_budget.py 的 Sobel/8、16×16 窗和合法像素定义。每个待评估分辨率由相同的 100 个固定训练访问、两侧所有合法格单独标定 1/3 分位，保存 pair ID、分母、阈值。开发和正式名单均与标定隔离。各分辨率的 LT 群体可能不同。

## 数据与训练公平性

manifests/hashes.json 保存历史来源与可迁移快照的 SHA-256。训练清单为官方 train_list 的 8,862,673 个 overlap>0 行，6,105,188 个物理无向对。按 scene 跨 bin 统一物理身份。单 epoch 对全部合法行做固定种子的无放回置换，训练 cursor 只在 optimizer update 后提交，每对的增广和细窗随机性按固定访问位置独立派生。默认使用原配置无增广；可统一设置 brightness。各模型使用相同数据顺序、训练预算、有效 batch 16。每对独立算 loss，microbatch 内均值再按 micro/16 累积。不能从已训练 P2 初始化 P3。

P1/P2 在可用的全部合法行列上计算原 90% 正例双向 focal（FP32 流式计算被采样的行列），使用原细窗 focal 及迭代坐标回归。P3/P4 的粗 focal 只对位于实际稀疏边集中的可靠几何正例，额外路由损失权重 0.1。P4 的可靠难负排序损失权重 0.1、margin 0.5。原 loss 系数 0.25/0.2/1。训练每对最多 1024 个父窗及 1024 个精修子点，原始全部预测仍参与验证。

所有微调组前 ceil(15%×总更新) 步冻结原特征主干，原匹配头和 RRU 可训练，存在的新模块也可训练。之后原权重 LR 2e−5、新权重 1e−4，AdamW、统一全程 cosine、grad clip 1。主干 BN 的均值/方差冻结；解冻阶段 BN 仿射参数默认参与梯度。数据、模型、粗 focal 抽样、细窗/噪声和注入随机流分开。记录实际 backbone 更新数及无可靠几何样本数。

Smoke 20+20，Short 1000+1000，Medium 5000+3000，单位均为 optimizer updates。单分辨率计划只使用第一段。Full 必须显式指定各段步数或 epoch 数。每 epoch 按 ceil(合法行/16) 个完整更新计，全程须达到行与物理对 100% 访问覆盖。指定 epoch 时，双分辨率按 5:3 分配更新，第一段向上取整。跨分辨率从上段固定步数的 checkpoint_last.ckpt 继承模型、优化器、cosine 时钟、cursor、RNG、覆盖率及热身进度。精度切换时重新初始化相应 scaler 并记录实际精度。

## 开发、封存与正式评价

MegaDepth 开发使用与训练及 1500 集场景互斥的 8×32 个固定图像对。TexturePoor 的验证场景为 1012、1026、1029，各 100 对。每段训练前后完整双验证。每 500 步在固定每场景一个样本的快速清单提名候选；段末对提名权重再作完整双验证，与固定末步在同一分辨率按 MegaDepth 场景等权 LT Recall 选择，并列取较早更新。开发信息缺失时采用预定末步。模块保留建议使用同对固定分母的场景等权 LT Recall 差和 seed 66 的 2,000 次整场景 bootstrap 区间，配合两路开发 AUC@10 与同卡中位延迟判断是否值得复验。最佳权重只参与选模、评测。跨段继承始终使用末步。

TexturePoor 的固定配对遵循原 bag 共现、各帧标定、无向去重、光轴角 [2°,85°]、基线 ≥0.005 和确定性难度分层。14 个测试场景×100 对。无逐点真值，仅报告两视图匹配、位姿及空间覆盖。MegaDepth-1500 保留全部 1500 个原始行；ScanNet-1500 由哈希锁定 test.npz 与 intrinsics.npz，原色图 K 从 640×480 标定缩放，C2W 转 T01=inv(C2W1)@C2W0。姿态用原生求解器、原像素 0.5 px、置信度 0.99999、seed 66，旋转与符号对称平移误差取大值。失败作为无穷进入 AUC@5/10/20，报告百分数、全局及逐场景与场景等权结果。极线阈值 1e−4，两侧 32 px 格覆盖率。主结果使用原生匹配输出，同时给出按原细窗双向概率稳定排序的最多 1,000 匹配两视图结果；后者独立保存在 capped_1000。HPatches 对固定 116×5 清单测原像素四角平均误差 AUC@3/5/10，失败保留。正式测试在 Full 拟训练组完成并写入模型、权重哈希、清单及代码冻结记录后启动。缺少数据的域单列 BLOCKED。

## 运行与测量

默认训练尝试 BF16，遇不支持的算子由隔离探测记录错误后改试 FP16 和 GradScaler。所有开发、正式及效率推理统一 FP16。逐架构/分辨率比较 1/2/4/8/16 真 microbatch 及 full/selective/off 激活重算，测解冻后的两个有效 batch（前置一次热身更新），包含状态初始化及验证切换。选择同时满足 allocator 目标和实际进程上限的最高实测 pairs/s。显存紧张时可缩小局部 chunk，边预算或候选定义保持冻结。

同步计时使用同一 checkpoint、同一固定 MegaDepth 开发图像序列、batch=1，每模型逐分辨率运行。默认 100 对、30 次预热、3 次重复，Smoke 只验收 2 对。单 R1024 筛选只测 R1024，渐进 Short/Medium/Full 执行 640/832/1024/1216 扩展。分开记录下载以外的实际磁盘读取、预处理、H2D、matcher、RANSAC 和端到端延迟。精确率/延迟和显存比较需参考同卡同负载记录，FLOPs 随附 profiler 未计数算子和样本身份。工程验收依据数值、梯度、状态、真实更新与资源保护。性能方向来自冻结评测。
